### 2026-08-03 — projection/browser motion evidence
- Source: `pitwall/dist/h3-evidence/FINDINGS.md`, real Chrome trace from demo-large at 100x speed.
- Value: one car produced `171 reversals / 318 frames`, worst direction cosine `-1.0`; raw coordinates retraced `(430.70,424.15)→(419.00,423.70)→(407.85,429.96)→(397.92,437.66)` and then the exact reverse sequence.
- Interpretation: `positionAt` cannot create bit-identical reverse traversal from increasing progress; input `visual` progress oscillated upstream.
- Refutes/Confirms: H3 REFUTED; H1 CONFIRMED. Likely seam is `projection.ts:Projector.step()` pull-back/lead-clamp.

## Root cause
`Projector.step()` accepted a backward target as the current anchor. The resulting lead clamp repeatedly cancelled the positive projected velocity, so the same visual position was returned after a backward correction. The fix keeps the last forward anchor whenever `shortest(anchor, target) <= 0`.
