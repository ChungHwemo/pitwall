### 핵심 결과 — 렌더 전략 가설이 검증됐다

**차량 100대 × 35,996프레임 = CSS `transform` 360만 회 쓰기가 layout을 한 번도 유발하지 않았다.**
남은 layout은 전부 **텍스트 변경**에서 나온다. 증거 두 가지:

- `chaos` 30초에 1,112회, **300초에도 1,128회.** 프레임이 10배 늘었는데 layout은 그대로다 — 이벤트가 끊기자(연료 소진) 누적이 멈췄다.
- 프리셋별 layout 순서가 차량 수가 아니라 **이벤트 발생률**을 따른다 (`busy` 0.86 > `chaos` 0.31 > `sparse` 0.04).

> **게이트 문구를 정정한다.** "프레임당 layout 0회"는 transform만 갱신한다는 전제로 쓴 기준이었다. **화면에 숫자가 바뀌면 layout은 반드시 1회 발생한다** — 이건 최적화 대상이 아니라 브라우저 동작이다. 올바른 기준은 **"layout이 프레임 수가 아니라 데이터 변경 횟수에 비례하는가"**이며, 실측이 이를 만족한다. Canvas 전환 검토 조건은 성립하지 않는다.

## ⚠️ 여전히 미측정

| 항목 | 합격 기준 | 상태 |
|---|---|---|
| **8시간 힙 증가** | ≤ 50 MB | **미측정.** 5분 실측에서 누수 징후는 없다 — 30초 +2.1 MB vs 300초 +1.8 MB로 **구동 시간에 비례해 늘지 않았고**, DOM 노드는 634 고정, 라디오 버퍼는 링버퍼로 상한. 그래도 8시간은 8시간을 돌려야 한다 |
| 실 GPU 프레임률 | 평균 ≥ 55fps | **부분 측정.** headless shell은 120fps 무제한으로 돌아 상한이 아니라 하한만 말해준다. 32ms 초과 프레임 0회는 유의미하나, 실제 컴포지터 경로는 헤드풀 브라우저로 재확인 필요 |
| 라디오 가독성 | `chaos`에서 읽을 수 있는 속도 | **미측정.** 사람의 판단이 필요하다 |
| 새 레이스 / 이어하기 | 새로고침 동작 | **미측정.** 세션 저장은 단위 테스트로만 확인 |

### 실행 방법

```bash
cd pitwall && npm run build && npm run preview   # 실측은 프로덕션 빌드로. dev 서버는 HMR이 측정을 깬다
```

프리셋은 `localStorage`의 `pitwall.settings`에 `{"preset":"chaos","speed":600}` 형태로 넣어 바꾼다.

```bash
# 정적 게이트 재실행
npm test && npx tsc --noEmit && npm run build
rg -i 'rank|leaderboard|timing-tower|<ol' src/render/ src/main.ts || echo "OK: no ranking UI"
rg "setAttribute\(['\"]transform" src/ || echo "OK: no SVG transform attribute"
rg 'getBBox|getComputedTextLength|createSVGPoint|getScreenCTM' src/ || echo "OK: no jsdom-hostile geometry"
```
