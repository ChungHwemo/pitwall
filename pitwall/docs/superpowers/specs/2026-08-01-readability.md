# PITWALL 가독성 최고급 구현 명세

**앰비언트 트랙맵과 이벤트 표면의 판독성 개선 계획**

작성일: 2026-08-01 · 대상: `src/render/trackRenderer.ts`, `src/config/theme.ts`, `src/style.css`, 이벤트 렌더러, F1 에셋 문서 · 범위: P0 3건, P1 2건

---

## 1. 목표와 판정 기준

PITWALL은 오래 응시하는 대시보드가 아니라 3초 동안 곁눈질해 상태를 읽는 화면이다. 이번 변경은 정보를 늘리는 것이 아니라 현재 정보를 더 빨리 분리해 읽도록 만드는 데 목적이 있다.

### 1.1 성공 기준

- 트랙 중심선과 피트레인이 배경에서 분리되되, 피트레인은 주행선보다 조용하게 보인다.
- 진행률 0의 스타트와 섹터 경계가 별도 텍스트 없이 즉시 읽힌다.
- 차량은 F1 차량 실루엣으로 보이고, H/P/GT는 색과 삼각형/원/사각형 배지로 동시에 구분된다.
- 색각 이상 사용자가 색을 보지 않아도 클래스 배지만으로 H/P/GT를 구분할 수 있다.
- 긍정 이벤트는 녹색, 오류와 한도 초과는 빨간색으로 같은 규칙을 피드, 무전, HUD에서 공유한다.
- `#F2C744` 계열의 따뜻한 노랑은 숫자 델타와 갭에만 쓰인다. 클래스, 경고, 장식에는 사용하지 않는다.
- 모든 SVG는 인라인 경로 문자열이며, 외부 요청과 런타임 의존성이 없다.
- 트랙 위에는 텍스트 라벨을 추가하지 않는다. 카넘버와 상세 정보는 기존 카메라 카드와 피드에서만 읽는다.
- 기존 644개 테스트, TypeScript 컴파일, 단일 파일 빌드가 계속 통과한다.

### 1.2 변경하지 않는 것

- 트랙 좌표 생성, 차의 진행률, 피트 박스 배치, 선택 동작, 보간 로직은 변경하지 않는다.
- 순위 UI, 새 데이터 수집, 개인정보 필드, 트랙 위 텍스트 라벨은 추가하지 않는다.
- 외부 `<image>`, URL 기반 SVG, 아이콘 패키지 의존성은 추가하지 않는다.
- 이 문서의 범위는 P0와 P1이다. 연료 링의 게이지화와 피트 박스 도구 아이콘은 포함하지 않는다.

## 2. 현재 상태와 근거

### 2.1 렌더러

`src/render/trackRenderer.ts`의 현재 차량 본체는 `glyphPath()`가 반환하는 삼각형, 원, 사각형 경로다. `hotSlot()`과 `coldSlot()`이 같은 `path` 노드를 재사용하고, `CLASS_STYLE`의 색과 형태를 그 노드에 적용한다.

현재 트랙 색상은 렌더러에 직접 박혀 있다.

| 요소 | 현재 값 | 문제 |
|---|---|---|
| 중심선 | `#2a323d` | 배경 `#0e1116` 대비 약 1.46:1 |
| 피트레인 | `#1c222b` | 배경 대비 약 1.18:1 |
| 스타트/피니시 | 없음 | 진행률 0을 즉시 찾기 어렵다 |
| 섹터 경계 | 없음 | `Track.sectors`는 `[0, 1/3, 2/3]`이지만 사용하지 않는다 |
| 차량 본체 | `glyphPath()` | 차량 의미보다 추상 도형으로 먼저 읽힌다 |

`src/style.css`의 트랙 영역은 `.detail` 안에서 SVG를 배치하고, 428행 이후 `brightness()`로 차량 발열을 표현한다. 새 아이콘도 기존 `g.car`, `g.cold`의 열과 불투명도 규칙을 상속해야 한다.

### 2.2 색상 체계

`src/config/theme.ts`에는 다음 색상이 있다.

- 배경: `BACKGROUND = '#0e1116'`
- H: 빨강 + 삼각형
- P: 파랑 + 원
- GT: 노랑 + 사각형
- 심각도: 정보는 청회색, 경고는 노랑, 치명적 상태는 빨강

이번 변경에서는 클래스용 색상, 이벤트 극성 색상, 숫자 강조 색상을 분리한다. 기존 GT 노랑과 경고 노랑은 `#F2C744` 계열을 독점하지 않도록 조정한다. 클래스는 형태 배지가 남아 있으므로 GT의 색상은 노랑이 아닌 보라 계열로 옮겨도 이중 인코딩 규칙을 위반하지 않는다.

### 2.3 에셋 규칙

`assets/f1/game-icons/f1-car.svg`는 Skoll의 Game Icons 에셋이다. 원본은 512×512 viewBox이며, 차량 실루엣의 본체 경로는 다음 값으로 고정한다.

## 3. 결정 사항

### 3.1 차량 표시 방식: F1 실루엣 + 별도 클래스 배지

세 클래스별 자동차 실루엣을 새로 만들지 않고, 하나의 F1 차량 실루엣에 기존 클래스 모양을 작은 배지로 결합한다.

이 방식을 선택한 이유는 다음과 같다.

1. 사용자가 요구한 `f1-car.svg`를 hot과 cold 차량에 동일하게 적용할 수 있다.
2. 하나의 차량 경로만 인라인하므로 번들 크기와 유지 비용이 가장 작다.
3. H/P/GT의 기존 의미인 삼각형/원/사각형을 별도 배지로 보존한다.
4. 차량 실루엣 자체가 클래스별 체형을 암시한다고 가정하지 않으므로 색만으로 의미를 전달하지 않는다.

#### 렌더 구조

각 `g.car`와 `g.cold`는 다음 순서의 자식을 갖는다.

1. `path.class-badge`: 클래스 배경과 테두리를 가진 작은 삼각형, 원, 사각형
2. `svg.class-car-icon`: `viewBox="0 0 512 512"`인 중첩 SVG
3. 기존 hot 전용 `fuelRing`
4. 기존 hot 전용 `alert`

`svg.class-car-icon`은 그룹의 원점 기준 `x=-9`, `y=-6`, `width=18`, `height=12`로 고정한다. 차량은 가로 18, 세로 12 user unit을 차지한다. 클래스 배지는 차량 아래 중앙 `x=0`, `y=8.5`에 두고, 반지름 또는 반폭은 2.5 user unit으로 고정한다. 배지는 차량의 실루엣을 가리지 않으며, 1.25 user unit 테두리를 둔다.

배지는 `glyphPath(style.shape, 2.5, 0, 8.5)`로 만든다. 배지의 내부는 `BACKGROUND`, 테두리는 클래스 색상으로 칠한다. 차량 본체는 같은 클래스 색상으로 칠한다. 따라서 다음 두 신호가 항상 함께 보인다.

| 클래스 | 차량 본체 | 배지 형태 | 배지 위치 |
|---|---|---|---|
| H | 클래스 색상 | 삼각형 | 차량 아래 중앙 |
| P | 클래스 색상 | 원 | 차량 아래 중앙 |
| GT | 클래스 색상 | 사각형 | 차량 아래 중앙 |

배지는 `aria-hidden="true"`로 두고 텍스트와 `data-car-id`를 추가하지 않는다. 위치 이동은 기존처럼 `g`에 CSS `style.transform`으로 적용한다. SVG `transform` 속성은 사용하지 않는다.

#### 원본 경로와 라이선스

- 경로 상수 이름은 `F1_CAR_PATH`로 정한다.
- `F1_CAR_PATH`에는 위의 흰색 본체 `d` 값만 넣는다.
- SVG가 생성되는 코드 바로 앞에 다음 HTML 주석을 그대로 둔다.

```html
<!-- Icon by Skoll, from game-icons.net, CC BY 3.0 -->
```

- 주석은 번들된 HTML에서 제거되지 않아야 한다.
- `assets/f1/game-icons/f1-car.svg` 파일 자체도 유지한다. 소스 파일은 검수와 라이선스 증빙용이고, 런타임은 경로 문자열만 사용한다.

## 4. P0 구현 항목

### P0-1. F1 차량 아이콘으로 차량 마커 교체

**대상:** `src/render/trackRenderer.ts`, `tests/trackRenderer.test.ts`

#### 작업

1. `glyphPath()`를 삭제하지 않는다. 클래스 배지와 섹터 또는 다른 도형이 같은 모양 규칙을 사용할 수 있으므로 배지 생성용으로 유지한다.
2. 기존 차량 본체 `SVGPathElement`를 F1 차량 아이콘을 담는 인라인 SVG 구조로 바꾼다.
3. hot과 cold 모두 동일한 F1 차량 경로를 사용한다.
4. hot 차량은 기존 연료 링과 정지 사유 표식을 유지한다. F1 차량 아이콘 교체가 상태 표식을 없애서는 안 된다.
5. cold 차량은 기존 `data-idle="true"`와 CSS 밝기 규칙을 그대로 적용한다.
6. 차량 색상은 `CLASS_STYLE[car.carClass]`에서 가져오고, 배지 테두리와 차량 본체에 같은 색상을 적용한다.
7. GT 클래스 색상은 숫자 강조용 따뜻한 노랑과 겹치지 않는 색으로 theme에서 변경한다. 모양 배지는 반드시 사각형으로 유지한다.

#### 테스트 우선 항목

구현 전에 다음 테스트를 추가하거나 기존 테스트를 확장한다.

- hot 차량의 SVG 하위 트리에 `viewBox="0 0 512 512"`인 차량 아이콘이 있다.
- cold 차량에도 같은 차량 아이콘이 있다.
- 생성된 DOM 또는 번들 소스에 F1 경로의 고유 구간 `M355.975 292.25`가 있다.
- H/P/GT 차량마다 `class-badge`가 하나씩 있고, 경로 형태가 각각 triangle/circle/square와 일치한다.
- 차량 본체와 배지 모두 클래스 색상을 사용한다.
- `<!-- Icon by Skoll, from game-icons.net, CC BY 3.0 -->` 문자열이 인라인 SVG가 생성되는 소스 또는 단일 HTML에 존재한다.
- track SVG 안에 차량 번호 텍스트가 생기지 않는다.
- 기존 클릭, 선택, hot/cold 풀 재사용, 정지 표식, 유휴 표시 테스트가 계속 통과한다.

#### 완료 조건

- 색을 끄고도 배지 형태로 세 클래스를 구분할 수 있다.
- 차량 아이콘이 기존 차 간격 테스트를 깨지 않는다. 아이콘의 시각적 폭을 고려해 겹침이 생기면 배지 크기를 먼저 줄이고, 좌표 모델이나 차 간격 로직은 바꾸지 않는다.
- `grep`으로 외부 URL, `<image>`, `<use>`가 차량 렌더 경로에 없는 것이 확인된다.

### P0-2. 트랙 가독성 개선

**대상:** `src/render/trackRenderer.ts`, `src/config/theme.ts`, `tests/trackRenderer.test.ts`, `tests/theme.test.ts`

#### 4.2.1 트랙 색상 토큰 중앙화

`src/config/theme.ts`에 다음 토큰을 추가한다.

```ts
export const TRACK_COLOR = {
  centerline: '#3f5963',
  pitLane: '#334b55',
  markerDark: '#11161d',
  markerLight: '#e8edf3',
  sector: '#6f8792',
} as const;
```

값의 의도는 다음과 같다.

- `centerline`은 `#0e1116` 대비 최소 2.5:1을 목표로 한다. 기준값 `#3f5963`은 약 2.54:1이며, 흰색처럼 튀지 않는 청록 회색이다.
- `pitLane`은 약 2.0:1 수준으로 중심선보다 낮게 유지한다. 기준값 `#334b55`는 피트 위치를 찾을 수 있지만 주행선과 같은 우선순위로 보이지 않는다.
- `markerDark`와 `markerLight`는 기존 `drawPitFlag()`의 체커 모티브에서 가져온다.
- `sector`는 중심선보다 밝지만 차량 클래스나 이벤트 색상과 섞이지 않는 청회색이다.

`trackRenderer.ts`의 중심선, 피트레인, 체커 스트립 색상에는 6자리 hex를 직접 쓰지 않는다. 모든 색상은 `TRACK_COLOR`에서 읽는다. `style.css`의 트랙 외 UI 경계선은 이번 중앙화 대상이 아니다.

#### 4.2.2 스타트/피니시 체커 스트립

진행률 0의 중심선 위에 스타트/피니시 스트립을 하나 그린다.

- 기준점: `track.points[0]`, 즉 `progress = 0`.
- 진행 방향 벡터: `track.points[1] - track.points[n - 1]`를 정규화한다.
- 횡단 벡터: 진행 방향을 90도 회전한 단위 벡터다.
- 전체 크기: 진행 방향 12 user unit, 횡단 방향 16 user unit.
- 격자: 횡단 방향 4칸, 진행 방향 2칸, 각 칸 4×6 user unit.
- 검은 바탕: 전체 16×12 직사각형을 `TRACK_COLOR.markerDark`로 채운다.
- 밝은 칸: `(row + column) % 2 === 0`인 4칸을 `TRACK_COLOR.markerLight`로 채운다.
- 회전: 각 사각형 좌표를 횡단 벡터와 진행 벡터로 직접 계산한다. SVG `transform` 속성은 사용하지 않는다.
- 클래스: `start-finish-marker`.
- 텍스트: 없음.

체커 스트립 중심은 `track.points[0]`에서 벗어나지 않는다. 기존 피트 플래그와 같은 체커 생성 패턴을 작은 순수 함수로 공유할 수 있지만, 피트 플래그의 위치나 크기는 변경하지 않는다.

#### 4.2.3 섹터 경계 틱

`Track.sectors`의 값 중 0이 아닌 경계인 `1/3`과 `2/3`에 짧은 수직 틱을 그린다.

- 경계 수: 2개. 스타트/피니시 스트립은 0 경계를 이미 표시하므로 별도 틱을 추가하지 않는다.
- 기준점: `positionAt(track, progress, 'P', 0)`과 동일한 중심선 위치 계산을 사용한다.
- 진행 방향: 해당 진행률의 앞뒤 점으로 계산한다. 폐곡선 끝에서는 배열을 순환한다.
- 틱 방향: 진행 방향에 수직인 횡단 벡터.
- 틱 길이: 중심선 양쪽으로 6 user unit, 총 12 user unit.
- 선 굵기: 2 user unit.
- 색상: `TRACK_COLOR.sector`.
- 클래스: `sector-marker`.
- 선 끝: `round`.
- 라벨: 없음. `S1`, `S2` 같은 텍스트를 트랙 위에 쓰지 않는다.

`sectors` 배열이 3개가 아닌 경우는 렌더하지 않고, 현재 모델 계약인 `[0, 1/3, 2/3]`에서는 항상 두 경계가 표시되도록 한다. 섹터 마커는 차량 클릭 대상이 아니며 `carLayer` 밖에 둔다.

#### 테스트 우선 항목

- 중심선의 `stroke`가 `TRACK_COLOR.centerline`이고, 피트레인의 `stroke`가 `TRACK_COLOR.pitLane`이다.
- `contrastRatio(TRACK_COLOR.centerline, BACKGROUND) >= 2.5`이다.
- `contrastRatio(TRACK_COLOR.pitLane, BACKGROUND) >= 2.0`이고 중심선 대비 피트레인의 상대 밝기가 낮다.
- 트랙 SVG에 `start-finish-marker`가 하나 있다.
- 스타트 스트립의 체커 칸 수가 4개이고, 전체 중심이 `track.points[0]`에 있다.
- `sector-marker`가 두 개이고, 진행률 `1/3`과 `2/3`에 대응하는 위치에 있다.
- 섹터 마커와 스타트 스트립이 차량 풀 또는 클릭 핸들러에 포함되지 않는다.
- 렌더러의 색상 문자열에 기존 `#2a323d`, `#1c222b`가 남지 않는다.

### P0-3. 모티브 기반 이벤트 가독성

**대상:** `src/config/theme.ts`, `src/render/feedRenderer.ts`, `src/render/radioRenderer.ts`, HUD 렌더러와 관련 테스트

#### 4.3.1 이벤트 극성 토큰

`theme.ts`에 이벤트 의미 전용 토큰을 둔다.

```ts
export const EVENT_POLARITY_COLOR = {
  positive: '#4ade80',
  caution: '#ff5c5c',
  neutral: '#9fb3c8',
} as const;
```

- positive: 추월, 증가, 이득, 정상 회복처럼 상태가 좋아지는 사건.
- caution: 오류, 한도 경고, 은퇴, 손실처럼 즉시 확인이 필요한 사건.
- neutral: 의미가 없는 상태 전달과 일반 정보.

기존 `SEVERITY_COLOR`는 무전의 심각도라는 이름을 유지할 수 있으나, `warn`에 `#ffd24d`를 다시 사용하지 않는다. 오류와 한도는 이벤트 극성의 `caution`을 사용한다. `critical`도 같은 빨강 계열을 사용하되, 굵기나 아이콘으로 한 단계 더 강하게 표시한다. 색만으로 `warn`과 `critical`을 구분하지 않는다.

#### 4.3.2 적용 위치

| 표면 | positive | caution | neutral |
|---|---|---|---|
| 피드 | 명시적 gain/overtake 또는 정상 회복 이벤트 | `status=error`, `kind=error`, `kind=limit_warn`, `kind=retire` | 일반 call과 정보 행 |
| 무전 | 회복, 이득, 추월을 알리는 메시지 | 문제 발생, 한도, 은퇴 메시지 | 포메이션, 피트 안내, 일반 상태 |
| HUD 델타 | 증가 또는 개선 방향의 이벤트 아이콘과 상태 문구 | 감소, 오류, 한도 초과 상태 | 변화 없는 값 |

현재 `CarEvent`에 추월이나 gain 필드가 없으면 데이터를 추정해 만들지 않는다. 그 경우 피드의 일반 `ok` 행은 neutral로 두고, 실제 polarity가 제공되는 이벤트만 positive로 칠한다. `status=error`와 `limit_warn`은 현재 계약만으로도 caution을 판정할 수 있다.

피드와 무전에는 `data-polarity`를 설정하고 CSS에서 색을 적용한다. 렌더러가 같은 이벤트를 여러 번 그릴 때 색상과 속성을 매 프레임 다시 쓰지 않는다. HUD도 같은 토큰을 사용해 표면마다 빨강과 녹색의 의미가 바뀌지 않게 한다.

#### 4.3.3 따뜻한 노랑의 단일 액센트 규칙

`#F2C744` 계열은 `ACCENT_DELTA`로만 정의하고 다음 숫자에만 사용한다.

- 전후 값의 델타 숫자
- 차량 또는 모델 간 갭 숫자
- 델타와 갭을 설명하는 최소한의 숫자 강조

다음에는 따뜻한 노랑을 사용하지 않는다.

- GT 클래스 색상
- 무전 `warn` 또는 `critical`
- 오류, 한도, 피트 상태
- 피드 행의 일반 강조
- 테두리, 배경, 장식, 섹터 마커

HUD를 전수 점검해 `#ffd24d`, `#F2C744`, `#f2c744`와 동일 계열의 리터럴을 찾고, 델타/갭이 아니면 `EVENT_POLARITY_COLOR`, 클래스 전용 색상, 청회색 중 하나로 옮긴다. GT 클래스는 사각형 배지가 있으므로 보라 계열 클래스 색상을 사용한다.

#### 테스트 우선 항목

- positive 이벤트의 피드, 무전, HUD가 `EVENT_POLARITY_COLOR.positive`를 사용한다.
- error, limit, retire 이벤트가 `EVENT_POLARITY_COLOR.caution`을 사용한다.
- neutral 이벤트가 청회색을 사용한다.
- `ACCENT_DELTA`가 델타와 갭 렌더링에서만 사용된다.
- GT 클래스와 warn 상태가 `ACCENT_DELTA`를 사용하지 않는다.
- 이벤트 polarity는 색상과 함께 `data-polarity` 또는 기존 형태 표식을 남겨 색상 단독 인코딩이 되지 않는다.

## 5. P1 구현 항목

### P1-1. 일반 자동차 아이콘의 보조 용도 배치

**대상:** 기존 카메라 카드 또는 피드 이벤트 행 렌더러, `src/style.css`, 관련 테스트

일반 자동차 아이콘은 트랙 차량 마커로 사용하지 않는다. 트랙의 모든 차량은 P0-1의 F1 실루엣과 클래스 배지를 사용한다.

세 generic car 에셋은 기존 피드 행의 이벤트 아이콘 슬롯에 배치한다. 새 데이터 필드는 만들지 않고 `CarEvent.kind`로 선택한다.

| 이벤트 | 아이콘 | 의미 |
|---|---|---|
| `call` 또는 일반 주행 호출 | `assets/f1/lucide/car.svg` | 일반 차량 활동 |
| `pit_in`, `pit_out` | `assets/f1/tabler/car.svg` | 피트 출입이 있는 차량 활동 |
| `retire`, `error`, `limit_warn` | `assets/f1/tabler/car-suv.svg` | 비정상 상태가 피드에 기록된 차량 활동 |

아이콘은 피드 행 첫 번째 열에 12×12 CSS pixel로 표시하고, `stroke` 또는 `fill`은 `EVENT_POLARITY_COLOR`가 아닌 neutral 청회색으로 둔다. 이벤트의 긍정/주의 의미는 행의 polarity 색과 기존 텍스트로 전달한다. generic 아이콘 자체는 클래스나 비용 등 어떤 값을 인코딩하지 않는다.

이 배치를 선택한 이유는 다음과 같다.

- 피드는 이미 이벤트별 행을 만들고 있어 아이콘의 수명과 이벤트 종류가 자연스럽게 일치한다.
- 트랙의 차량 마커와 화면 영역이 분리되어 두 아이콘 체계가 섞이지 않는다.
- 아이콘이 의미하는 것은 클래스가 아니라 이벤트 맥락이므로 색과 형태 이중 인코딩 규칙을 침해하지 않는다.
- 기존 피드의 모델, 주체, 토큰 수 정보와 함께 읽히며 별도 패널이나 새 UI 영역이 필요 없다.

SVG는 기존 단일 파일 정책에 맞춰 인라인한다. 원본 파일은 에셋 라이브러리에 남기고, 런타임에는 경로 문자열만 쓴다. 외부 `<img>`와 `<image href>`는 사용하지 않는다.

#### 테스트

- 세 이벤트 종류에 올바른 generic 아이콘 경로가 선택된다.
- generic 아이콘이 `g.car`, `g.cold`, `class-badge` 아래에 생성되지 않는다.
- 피드 아이콘에는 `car_id`, 이메일, 모델 원문 외의 개인정보가 추가되지 않는다.
- positive/caution 행의 색상은 generic 아이콘 색상과 독립적으로 유지된다.
