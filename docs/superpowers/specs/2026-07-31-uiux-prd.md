## 2. 하지 않을 것 — 먼저 못박는다

### N1. 스킬 판을 세우지 않는다 [High]

로그에 `attributionSkill`이 있으니 만들 수는 있다. **커버리지가 막는다.**

이 기기 실측(usage 9,739행 · 작업 토큰 66,258,097):

| 축 | 귀속 작업 토큰 | 비중 |
|---|---|---|
| 스킬 | 4,465,212 | 6.7% |
| MCP 툴 | 1,493,995 | 2.3% |
| 귀속 없음 | ≈ 60,299,000 | **91.0%** |

스킬 판은 6.7%를 화면 한 칸으로 승격시킨다. 곁눈질 화면에서 한 칸은 "이게 전부"로 읽힌다.
`spent`의 효율 점수를 기각한 이유(벤치마크 R2)와 **같은 고장**이다.

**대신**: 이미 하는 것으로 충분하다 — 피드 행의 스킬 칸. 계정을 고른 사람만 보고,
전체를 대표한다고 주장하지 않는다. **추가 작업 0.**

**재검토 조건**: 스킬 귀속 비중이 3개월 이동 중앙 **40%**를 넘으면 다시 연다.

### N2. 훅·프록시로 수집하지 않는다 [High]

`Claude-Code-Agent-Monitor`(858★)는 Claude Code 훅으로 즉시 수집한다. 폴링 2초보다 빠르다.
**그리고 실행 경로 안에 들어간다.** 느린 훅은 에이전트를 멈춘다.
프록시를 기각한 것과 같은 선이다 (벤치마크 R3). 상시 노출 화면이 작업을 멈출 수 있는 자리에 있으면 안 된다.

### N3. 계정이 적을 때 빈 공간을 채우지 않는다 [Medium]

계정 1개면 화면의 70%가 검다. **그것이 사실이다.** 채우면 거짓이 된다.

그리드 비율을 계정 수로 바꾸는 안은 기각한다 — `PITWALL.md §10`에 이미 잡힌 버그
("선택 시 맵 밀림 — 그리드 행 비율이 바뀜")를 열 방향으로 되살린다.

## 3. 할 것

### P0-1. 카넘버가 잘린다 — 화면이 틀린 숫자를 말한다 [High]

**증상.** 계정이 10대를 넘으면 3자리 카넘버의 마지막 자리가 잘린다.
`233`이 `23`으로, `874`가 `87`로 읽힌다. 스크린샷에서 3자리 10개가 **전부** 잘렸다.

**기전 (실측 확인).**

| 값 | 출처 |
|---|---|
| dense 카넘버 칸 폭 | `3rem` = **48px** — `style.css` `.tower[data-dense="true"] .tower-row` |
| `"874"` 실제 폭 | **54.19px** — 1.875rem(30px) · weight 700 · SF Mono, 헤드리스 측정 |
| 넘침 | **6.19px** |
| 자르는 규칙 | `.tower-row > * { overflow: hidden }` |
| 발동 조건 | `DENSE_FROM = 10` (`towerRenderer.ts:95`) |
| 3자리 비율 | `car_number = hash % 999 + 1` → 약 90% |

비-dense 칸은 `4rem` = 64px라 들어간다. **계정이 많을 때만, 즉 볼 이유가 가장 큰 때만 깨진다.**

**고침.** dense 카넘버 칸 `3rem` → `3.6rem`(57.6px, 여유 3.4px). 줄어드는 것은 같은 줄의
`1fr` 칸(스파크라인)이고 dense에서 그 칸은 이미 여유가 있다. 한 줄.

**회귀 방지.** jsdom은 레이아웃을 계산하지 않아 테스트로 못 잡는다 — 이것이 지금까지 안 잡힌 이유다.
`--tower-min` 주석이 쓰는 것과 같은 방식으로 **칸 폭 산수를 CSS 주석에 남기고**,
헤드리스 캡처를 스크립트 하나로 재현 가능하게 만든다 (§5).

### P1-1. 피트에 선 차들이 한 덩어리로 겹친다 [High]

**증상.** 정지 차량 9대가 서로 겹쳐 세 종류 글리프(한도 노랑 · 에러 빨강 · 유휴 파랑)를
구분할 수도, 셀 수도 없다. 대규모 데모에서 정지 차량이 **12대 중 9대** — 다수가 읽히지 않는다.

**기전.** `layout.ts:65` `pitBoxAt(track, slot, _slots)`가 **`_slots`를 안 쓴다.**
간격은 `PIT_BOX_GAP = 0.008` 고정이고, 그 진행률이 코스에 따라 글리프 지름보다 짧아진다.
`pitLanePoints(track, boxes = 8)`도 8칸만 그려서 9번째부터는 레인 밖이다.

**고침.** 시그니처에 이미 있는 `_slots`를 쓴다 — 레인 길이를 고정하고 간격을
`min(PIT_BOX_GAP, LANE_SPAN / max(1, slots - 1))`로 압축, 레인은 `max(8, slots)`칸으로 그린다.
밑줄 하나 떼는 수준.

**상한.** 압축해도 안 되는 규모(> 20대)는 `LaneAssignment.clustered`가 이미 쓰는
`+N` 배지 패턴을 그대로 쓴다. 새 패턴을 만들지 않는다.

### P1-2. 좁은 창에서 조작판이 컨트롤 한가운데를 자른다 [High]

**증상.** 1440×900 + 데이터셋 선택 + `지어낸 데이터` 배지 조합에서 `한도` 하이라이트 체크박스가
**파란 조각만 남고** 라벨이 사라진다. 켜졌는지 꺼졌는지 알 수 없다.

**기전.** `.settings { overflow: hidden }`. "넘치면 설정이 먼저 잘린다"는 의도는 맞지만,
잘리는 단위가 **위젯 중간**이라 결과가 고장으로 보인다.

**고침.** 범례가 이미 쓰는 패턴을 재사용한다 — `⚙` 토글 하나로 접고, 열면 `fixed` 패널.
`.legend` / `.legend-body` 규칙을 그대로 따른다. 새 상호작용 없음.

### P1-3. HUD에 위계가 없고, 죽은 항목이 자리를 점유한다 [Medium]

**증상 1.** 상단 바 8개 항목이 전부 `1.05rem` 같은 굵기다 —
`07/30 07:31 · 00:31:00 / 15:00:00 · $0.67 · $1.3/시간 · 3.2k tok/분 · RACING · 💰 연봉 미설정`.
곁눈질 화면에서 무엇도 먼저 도착하지 않는다.

**고침.** `$총액`과 `tok/분` 두 개만 한 단 키운다(`1.05rem` → `1.35rem`). 새 요소 0개.

**증상 2.** `💰 연봉 미설정`이 값이 없는 채로 프라임 자리를 영구 점유한다.
연료 예산의 출처는 `PITWALL.md §11`에서 **미결**로 남아 있는 항목이다.

**고침.** 값이 없으면 항목을 안 그린다. 설정 패널에는 남긴다.

### P1-4. 죽은 필드 두 개를 지운다 [High]

| 필드 | 실측 | 판정 |
|---|---|---|
| `CarEvent.agent` | `claudeCodeImport.ts:89`가 `attributionAgent`를 읽는데 **그 키가 37,814행에 없다** → 항상 `undefined` | 삭제 |

피드 행이 4칸 → 3칸이 되어 항상 비어 있던 칸이 사라진다.

## 5. 검증

**문제**: jsdom은 레이아웃을 계산하지 않는다. P0-1·P1-1·P1-2는 **테스트 579개를 전부 통과한 채로 존재해 왔다.**
같은 종류를 또 놓치지 않으려면 픽셀을 보는 경로가 하나 필요하다.

**가장 게으른 경로** — 이미 설치된 Chrome을 헤드리스로 부른다. 새 의존성 0개.

```bash
npm run shot            # dist/pitwall.html → docs/screenshots/YYYY-MM-DD-*.png (1440×900, 데이터셋 2종)
```

`localStorage`에 데이터셋을 심은 사본을 만들어 `--headless=new --screenshot`으로 찍는다.
이번 조사에서 쓴 방법 그대로이고, Playwright·Puppeteer를 넣지 않는다.

## 6. 악마의 변호인 — 초안이 틀린 곳

초안의 주장을 브라우저 계측(`Range.getBoundingClientRect` · `scrollWidth` · 실행 중 DOM 덤프)으로
다시 쟀다. 세 건이 뒤집혔다.

### D1. P0-1의 **고침**이 틀렸다 — 원인 진단은 맞았다 [High]

초안: "dense 카넘버 칸 `3rem` → `3.6rem`". 근거로 든 `root = 16px`는 **틀렸다.**
헤드리스 1440×900의 실제 뷰포트는 1440×**813**이라 `min(100vw/90, 100vh/56.25)`가
세로에서 결정되어 **14.4533px**다. px로 세운 산수 전부가 이 값에 물려 있었다.

다시 재니 rem으로는 같은 답이 나왔다 — 계측값 `"540"` 글리프 폭 48.9px ÷ 14.4533 = **3.383rem**,
칸 3rem. 결론은 살았지만 **근거를 px로 쓴 것이 잘못**이었고, 코드 주석은 rem으로 고쳤다.

부수 확인: 칸을 넓히면 같은 줄 `1fr`(스파크라인)을 빼앗는다. 스파크라인은 18칸 ×
0.95rem × 0.66 ≈ 11.3rem이 필요하고 그 칸은 13.2rem이라 0.6rem을 내주고도 들어간다.
(모델 칸 185.3px·스파크 칸 266.3px 예측이 계측과 **소수점까지 일치**해 이 모델을 신뢰한다.)

### D2. P1-1의 고침 공식이 **아무것도 안 바꾼다** [High]

초안: `min(PIT_BOX_GAP, LANE_SPAN / max(1, slots - 1))`.
`LANE_SPAN = 8 × PIT_BOX_GAP = 0.064`이므로 정지 9대에서
`min(0.008, 0.064 / 8) = 0.008` — **원래 값 그대로다.** 관측된 겹침이 정확히 9대에서
났으니 이 고침은 관측된 사례를 못 고친다.

더 캐 보니 원인 후보가 바뀐다. 피트 박스는 **중심선 진행률**로 띄우는데 그리기는
`PIT_LANE_OFFSET`만큼 **안쪽으로 밀어서** 그린다. 겹친 스크린샷의 피트 레인은
헤어핀 안쪽이고, 안쪽으로 민 곡선은 중심선보다 짧으므로 같은 진행률 간격이
픽셀에서 압축된다. **간격을 중심선이 아니라 실제 피트 레인 폴리라인의 호 길이로 재야 한다.**

**측정으로 확정하지 못해 착수하지 않았다.** 재현 시점을 잡지 못했다 —
확인 시도에서 정지 차량이 최대 1대까지만 잡혔다. 관측된 사실(겹침)은 스크린샷으로
확실하고, 기전은 [Medium]이다. 재현 조건부터 만드는 것이 다음 순서다.

### D3. P1-3의 "`tok/분`만 키운다"는 **실행 불가능했다** [Medium]

`$총액 · $/시간 · tok/분`은 `formatPace`가 만드는 **한 문자열**이고 요소도 하나다.
하나만 키우려면 요소를 셋으로 쪼개야 하는데, 쪼개서 하나만 키우면 나머지 둘이
옆에 작게 남아 오히려 시선이 갈라진다. 덩어리 하나를 통째로 키우는 것으로 바꿨고,
주석도 하는 일에 맞게 고쳤다 — **코드가 못 지키는 근거를 주석에 남기지 않는다.**

### D4. 초안이 못 본 것 — 고른 차가 없을 때 안내문이 안 보인다 [High]

수정 후 화면을 다시 찍다가 발견했다. 선택이 없으면 `.cams`가 `2.1rem`으로 접히는데,
`.feed-number`가 `—`를 1.6rem으로 찍어 그 높이를 다 먹어 **안내문이 잘려 있었다.**
지도 옆에 뜻 모를 대시 하나만 떠 있었다 — 안내하려고 남긴 자리가 안내를 가렸다.
제목을 비우는 한 줄로 고쳤다. **P0-1을 확인하려고 만든 경로가 바로 다른 것을 잡았다.**

### D5. 뒤집히지 않은 것

N1(스킬 판 기각) · N2(훅 기각) · N3(빈 화면 유지) · P1-4(죽은 필드 삭제)는
데이터 실측에 직접 걸려 있어 재검토에도 그대로다.

| D4 | 선택 없을 때 `—` 대신 안내문 | `feedRenderer.ts` |

**스킬 무전이 N1을 어기지 않는 이유.** 무전은 "지금 #710이 이 스킬에 들어갔다"만 말한다.
비중을 주장하지 않으므로 6.7%가 100%인 척하지 않는다. 진입만 알리고 종료는 안 알리는데,
귀속이 6.7%뿐이라 "다음 호출에 스킬이 없다"가 스킬이 끝났다는 뜻이 아니기 때문이다.

**측정.** `npm test` 586개 통과(43파일) · `npx tsc --noEmit` 클린 ·
`npm run shot` 재촬영으로 카넘버 10개 전부 온전, 조작판 `에러`·`한도` 둘 다 보임,
무전에 `#710 — 스킬 — superpowers:test-driven-development` 출력 확인.
조작판은 `설정` 버튼으로 접히고, 열면 `배속`·`하이라이트 에러/한도`가 잘림 없이 나온다.

**남은 것.** 범례와 조작판이 같은 자리(`right: 0.6rem; top: 3rem`)에 뜬다 — 둘 다 열면
겹친다. 상호 배제를 넣지 않은 이유는 관측된 적이 없기 때문이다. 겹침이 실제로 걸리면
그때 넣는다.

## 8. 미결

- **`npm run shot` 산출물을 커밋할 것인가.** 매번 바뀌는 PNG는 diff가 무의미하다.
  회귀 검사용으로만 쓰고 커밋은 사건이 있을 때만 — 지금 `docs/screenshots`가 하는 방식 그대로.
- **스킬 귀속 6.7%가 이 기기만의 값인지.** 계정 1개 · 하루치다. 다른 기기 표본이 없다. [Low]
- **`isSidechain` 0건이 하네스 버전 탓인지 사용 패턴 탓인지.** `claudeview`는 `subagents/` 경로를
  전제로 하는데 이 기기에는 그 디렉터리가 없다. 서브에이전트를 실제로 쓰는 기기에서 재측정해야
  N1·P1-4의 `sidechain` 판정을 확정할 수 있다. [Medium]
- **P1-1 재현 조건.** 정지 차량 9대가 동시에 서는 시점을 다시 만들어야 D2의 기전
  (중심선 진행률 vs 오프셋 폴리라인 호 길이)을 확정할 수 있다. 그 전에는 고치지 않는다.
- **`npm run shot`의 뷰포트가 앱 창과 다르다.** 헤드리스는 1440×900 요청에 1440×813을 준다.
  비율은 rem으로 고정이라 잘림 판정은 같이 나오지만, **절대 px를 이 화면에서 읽으면 안 된다** —
  초안이 정확히 그 함정에 빠졌다 (§6 D1).
