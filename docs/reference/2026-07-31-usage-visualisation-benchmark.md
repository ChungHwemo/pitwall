## 0. 결론 먼저

같은 로그를 읽는 도구가 **최소 20개**다. 전부 대시보드·메뉴바·TUI다.
**전체 화면 앰비언트로 만든 것은 없었다** — 그게 PITWALL의 자리다.

다만 우리가 유일하다고 여기던 것 중 셋은 이미 남이 하고 있고, 하나는 **더 잘** 한다.

| 항목 | 우리 | 남 |
|---|---|---|
| 키체인에서 Claude 한도, `~/.codex/auth.json` | 있음 | `toki-monitor`도 **똑같이** |
| 5시간·7일 창 + 리셋 카운트다운 | 있음 | `toki-monitor`도 있음 |
| 연료 게이지 은유 | 있음 | `tokentap`이 먼저 (`fuel gauge`) |
| 속도를 캐릭터 움직임으로 | 있음 (차) | `toki-monitor`가 **시그모이드로 더 잘** |
| 툴 콜 단위 귀속 | **없음** | `tokview`가 함 |
| 순위표 | **거부** | `tokens.ci`는 그게 제품 |

## 2. 가져올 것

### B1. 속도→움직임 매핑을 시그모이드로 [High]

`toki-monitor`의 토끼는 **토큰 속도가 오르면 빨리 뛴다.** 그냥 비례가 아니라
**시그모이드**이고, README가 기울기가 가장 가파른 구간을 명시한다 —
**500~3,000 tok/분**. 유휴면 `zZ`를 띄우고 잔다.

우리 차의 속도는 누적 작업 토큰이라 **선형**이다. 계산해 보면:

| 속도 | 바퀴/시간 | 화면 속도 |
|---|---|---|
| 200 tok/분 | 0.24 | **0.06 px/초** |
| 500 | 0.60 | 0.14 px/초 |
| 1,000 | 1.20 | 0.28 px/초 |
| 3,000 | 3.60 | 0.85 px/초 |
| 5,000 | 6.00 | 1.42 px/초 |
| 12,000 | 14.40 | 3.40 px/초 |
| 40,000 | 48.00 | 11.33 px/초 |
| 137,000 | 164.40 | 38.82 px/초 |

**읽히는 구간이 위쪽에 몰려 있다.** 실측에서 흔한 500~5,000 tok/분이 전부
0.14~1.4 px/초로, 곁눈질에는 전부 "안 움직임"으로 보인다. 반대로 바쁜 계정은
39 px/초로 흐른다. 남이 시그모이드를 쓴 이유가 이것이다.

**단, 그냥 베끼면 안 된다.** 속도를 비선형으로 만들면 **바퀴 수가 토큰 수와
어긋난다** — "한 바퀴 = 작업 토큰 5만"이 깨진다. 우리 화면은 위치가 곧 누적량이고
저쪽은 위치에 의미가 없다(제자리 달리기). 채택하려면 **바퀴는 누적으로 두고
글리프의 부수 표현**(꼬리 길이·펄스 주기)에 시그모이드를 걸어야 한다.

### B2. 유휴를 자는 것으로 [Medium]

토끼는 유휴면 `zZ`를 띄우고 잔다. 우리는 `IDLE` 배지 + 스파크라인 회색인데,
**정지한 차와 유휴한 차가 트랙에서 똑같이 안 움직인다.** 피트는 정지 전용이므로
유휴는 트랙 위에서 구분돼야 한다.

### B3. 툴 콜 단위 귀속 [Medium]

`tokview`가 **툴 콜 단위**로 토큰을 쪼갠다 — 프록시로 감싸서 얻는다.
우리는 `agent`·`skill`까지만 알고 그 아래가 없다. 로그만 읽어서는 못 가는 층이라
프록시가 필요하고, 그건 v1 범위 밖이다.

`tokview`가 붙인 단서 하나는 그대로 가져올 만하다 —
**툴 단위는 토큰으로만 말하고 달러로 환산하지 않는다.** 과금은 모델 호출 단위이고
캐시 할인이 섞여서 툴별 달러는 오해를 만든다.

### B4. 캐시 성능을 1급 지표로 [High · 이미 부분 반영]

`claude-lens`가 `cache performance`를 대시보드 축의 하나로 둔다.
우리는 조직 합계 줄에 `캐시 99%` 한 칸이다. 실측 캐시 비중이 **98~99%**인데
그 한 줄이 전부인 것은 비중에 비해 작다.

### B5. 프로젝트 단위 분해 [Medium]

`toki-monitor`는 **프로젝트별** 토큰 분해를 한다("smart path recovery").
우리는 계정 → 모델까지만이고 **어느 저장소에서 태웠는지**가 없다.
`cwd`는 로그에 있지만 PRIV 규칙(경로 미노출)과 부딪힌다 — 해시로 넣거나 안 넣거나다.

## 3. 가져오지 않을 것

### R1. 순위표 — `tokens.ci`

`missuo/tokens`는 **"AI 코딩 사용량 공개 순위표"**가 제품이고 `Hall of Shame`
페이지까지 있다. iOS 위젯으로 순위를 띄운다.

PITWALL은 정확히 이것을 **안 만들기로** 되어 있다 (PRD PRIV-2).
타워 줄이 카넘버 고정 순서인 이유가 그것이고, 정렬 키를 사용량으로 바꾸는 순간
같은 물건이 된다. 잘 팔릴 수는 있어도 우리 것이 아니다.

### R2. 효율 점수 — `spent`

`loplop-h/spent`는 `efficiency score`와 `productive vs wasted` 분해를 낸다.
**무엇이 낭비인지 판정하는 근거가 없다.** 재시도가 낭비인지 탐색인지 로그로는
구분되지 않는다. 없는 판정을 숫자로 만들면 화면이 거짓말을 한다.

### R3. 프록시로 감싸기 — `tokentap` · `tokview`

둘 다 에이전트를 프록시로 감싼다(`tokview wrap claude`). 얻는 게 많지만
**실행 경로에 끼어든다** — 프록시가 죽으면 에이전트가 죽는다. 상시 노출 화면이
작업을 멈출 수 있는 위치에 있으면 안 된다. 우리는 로그만 읽는다.

### R4. 서버·계정 — `openclaw-dashboard` · `agentsview`의 S3

인증·MFA·원격 소스는 조직 배포의 문제고 v1은 로컬이다. (이미 문서화됨)

### R5. PromQL 대시보드 — `toki-monitor`

패널마다 PromQL을 돌린다. 강력하지만 **질의를 짜야 읽히는 화면**은 앰비언트가
아니다. 우리가 카드를 없애고 타워로 간 이유와 같은 판단이다.

## 4. 우리만 하는 것

조사 대상 20개 중 **어느 것도** 다음을 하지 않는다.

1. **전체 화면 앰비언트.** 전부 메뉴바·TUI·브라우저 탭이다. 두 번째 모니터에
   띄워두고 곁눈질하는 물건은 없었다.
2. **계정을 나란히.** 대부분 "내 사용량"이다. 조직의 여러 계정을 한 화면에 세우는
   것은 `codelight`·`agentsview` 정도인데 둘 다 표다.
3. **세 축 분리** (랩 / 레이스 / 한도). 다른 도구는 한도와 사용량을 같은 게이지에
   섞는다. `tokentap`의 연료 게이지도 컨텍스트 창 하나다.
4. **정지 사유 구분.** 에러와 한도를 다른 표식·다른 색으로 나누고 피트로 보낸다.
   다른 도구는 색상 단계(초록→노랑→빨강)만 쓴다.

## 5. 확인한 사실과 아닌 것

- 별 수·설명·기능 목록은 **README에서 직접 읽었다**.
- 스크린샷·GIF는 **열어보지 않았다** — 화면 구성 평가는 README 텍스트 기준이다.
- `toki-monitor`의 시그모이드 구간(500~3,000 tok/분)은 README 명시값이고
  **코드로 검증하지 않았다**.
- 우리 속도표(0.06~38.8 px/초)는 랩 5만 토큰·둘레 약 850px 가정의 산술이다.
